# meow: quasisymmetric equilibrium optimization

An offline, 35-slide presentation in the repository's Technical Blueprint style.

- [Open the presentation](index.html)
- [16:9 PDF](meow.pdf)
- [Evidence, revisions, and measurement limits](evidence.md)

The first part explains the C++20 TRF optimizer, boundary parameterization,
cuMES integration, and Jacobian strategies. The second follows the Landreman–Paul
QA/QH construction runs and compares the original reference fields with new
cuMES solves of the published boundaries.

The evidence does **not** support a qualified end-to-end tangent speedup. Early
tangent runs were faster but reached worse objectives; corrected tangent runs
were slower than the historical cold controls. The measured 2.727× QA / 2.648×
QH construction speedups belong to four-worker finite differences plus Broyden
reuse. The slides make this attribution explicit.

## Present and edit

Open `index.html` directly or, from the repository root:

```bash
python3 -m http.server 8000
```

Visit `http://localhost:8000/slides/meow/`. Use arrows, Home/End, `O` for overview,
`N` for speaker notes, `?` for help, and `F` for fullscreen. Touch devices support
horizontal swipes and vertical scrolling. Wide figures and tables scroll
horizontally on small screens. KaTeX, fonts, and presentation assets are local.

Edit `scripts/build_deck.py`, then regenerate from the repository root:

```bash
python3 slides/meow/scripts/build_deck.py
```

`styles.css` and `deck.js` originate from the existing cuMES decks; `meow.css`
adds the measurement and figure layouts. The generator uses the shared controls
markup at the end of `slides/cumes-run/index.html`. Edit the generator rather
than its generated `index.html`.

The generator applies the shared `../../scripts/inline_math.py` formatter to
variables and quantities in prose, tables, captions, and notes. Use
`inline(r"...")` for complete or ambiguous expressions, and `<code>` for literal
program text. Figure labels use Matplotlib mathtext; SVG glyph outlines are
embedded so presentation does not depend on installed scientific fonts.

## Figures and saved evidence

```bash
python3 slides/meow/scripts/plot_results.py
python3 slides/meow/scripts/build_deck.py
```

This needs Python, NumPy, and Matplotlib. It reads only this deck's frozen data
and does not run a solver. SVG charts retain vector labels; 3-D surfaces and
Boozer contour plots are rendered to PNG. All figures are original plots of
the saved numerical data, not copied paper figures. QA construction geometry is
rigidly rotated by π/nfp for visual phase alignment; inputs and objective values
are unchanged.

`data/archived/` preserves available historical timing files, logs, and boundary
checkpoints. `data/reference/` contains evaluated VMEC target profiles, boundary
coefficients, and selected original BOOZ_XFORM spectra. The full NetCDF archive is
not duplicated. `data/source-manifest.json` records the original paths and
SHA-256 fingerprints. `data/inputs/` contains the meow example inputs and two
deck-authored four-worker rundowns with explicit Broyden settings.

To refresh the original evidence from the sibling repositories and the extracted
Zenodo v2 dataset:

```bash
python3 slides/meow/scripts/collect_evidence.py
```

This also needs SciPy and reads the source tree named in `evidence.md`. It copies
existing benchmark artifacts and re-evaluates archived VMEC fields on the CPU;
it does not rerun historical optimizations. Preserve this campaign before
refreshing it from a different checkout. The current four-worker rundown variants
are editable inputs and are not generated by this collection script.

## Reproduce the new accuracy checks

The saved September 8 checks used meow `de1b324` with its pinned cuMES
`f61c959334bb62e14c049c66335580b45f63610d`, built in
`../tmp/meow-fetch-public-f61c959`. That build was up to date before the runs.
To make a fresh integration build from the same meow revision:

```bash
cmake -S ../meow -B ../tmp/meow-slides-build \
  -DMEOW_BUILD_CUMES_INTEGRATION=ON \
  -DMEOW_FETCH_CUMES=ON \
  -DCMAKE_BUILD_TYPE=Release
cmake --build ../tmp/meow-slides-build -j 6
python3 slides/meow/scripts/reproduce_equilibria.py \
  --build ../tmp/meow-slides-build \
  --output ../tmp/meow-slides-accuracy-new
```

The output directory must be new. The script records inputs, executable hash,
GPU state, source revisions, build cache, commands, residuals, and full target
profiles. These are one-shot **accuracy checks**, not timing benchmarks. A
different meow/cuMES revision may change the converged field and QS value.

To inspect a current optimization configuration or run only its first stage:

```bash
../tmp/meow-slides-build/cumes_landreman_optimize --dry-run \
  slides/meow/data/inputs/qa-four-worker.rundown.json
../tmp/meow-slides-build/cumes_landreman_optimize \
  --last-step mode-1 \
  --output ../tmp/meow-slides-qa-mode1.json \
  slides/meow/data/inputs/qa-four-worker.rundown.json
```

Use `qh-four-worker.rundown.json` and a distinct output for QH. Remove the stage
limit for full construction. A current run is not a reproduction of the
September 2–4 wall measurements unless the old implementation, dependency,
configuration, and measurement conditions are also restored; historical commands
used the former positional CLI.

## Validation and PDF export

```bash
node --check slides/meow/deck.js
python3 slides/meow/scripts/validate_deck.py \
  --chrome ../tmp/google-chrome/opt/google/chrome/chrome \
  --scratch ../tmp/meow-slides-20260908/preview
git diff --check
```

Supply a local Chrome/Chromium path. The validation script needs `requests`,
`websocket-client`, and Pillow; it starts and closes its own headless browser.
It captures every slide, checks 1600×900 and 1280×720 layouts, equation and image
loading, metadata, keyboard navigation, overview, notes, help, touch swipes, and
print layout, then writes `meow.pdf` and `data/validation.json`. Contact sheets
and screenshots remain in the scratch directory. PDF output uses 35 pages at
13⅓ × 7½ inches. Visual review of screenshots is still needed for chart labels
and readability that DOM checks cannot establish.

The validator also checks that inline math renders, preserves letter case, fits
its container, and survives copying into the notes overlay. To inspect another
deck, pass `--deck slides/<topic>`; `--pdf` and `--report` override output paths.

No complete historical optimization, solver test suite, new Boozer transform,
SPEC calculation, or particle-orbit campaign was run for this deck. See the
evidence ledger for the exact scope of the QA/QH reproduction.
